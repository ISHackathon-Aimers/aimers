# AIMers

대학생의 경험을 기록하고 AI 질문으로 구체화해 면접·자소서·학기 회고에 활용하는 웹 앱입니다.

## 실행

Node.js 24 이상이 필요합니다. 외부 패키지 설치 없이 실행합니다.

```powershell
node server.mjs
```

저장소 루트의 `start-aimers.cmd`도 사용할 수 있습니다. 접속 주소는 `http://127.0.0.1:4173`입니다.

`aimers-app/.env`를 자동으로 읽습니다. `.env.example` 형식으로 `DEEPSEEK_API_KEY`를 설정합니다. 기본 모델은 `deepseek-flash`이며 `DEEPSEEK_MODEL`로 변경할 수 있습니다. 키가 없어도 원문 기록과 기본 통계는 사용할 수 있습니다. 키는 서버에서만 사용하며 빌드 산출물에 포함하지 않습니다.

## 화면과 기능

- **대시보드:** 기록 추가, 설정한 주기에 맞는 회고, 현재 기간과 마감, 완료 여부, 연속 완료 횟수, 세 탭의 주요 내용.
- **내 기록:** 작성·수정·삭제, 원문·정리본, 검색, 날짜/카테고리 정렬, 카테고리 추가, JSON 가져오기·내보내기.
- **내 그룹:** 그룹 목록과 상세, 각 멤버의 개인 주기별 작성 여부, 콕 찌르기, 멤버 프로필, 전체 공개 기록 둘러보기.
- **부가 서비스:** 경험·카테고리별 면접 예상 질문, 자소서 문항에 맞는 경험과 추천 이유, 학기별 통계 및 AI 비교.
- **우측 상단 프로필:** 사진, 기본 공개 범위, 주기·시작일, 연속 기록 기간, 글꼴·글씨 크기.

새로운 로컬 사용자에게 예시 기록 8개가 생성됩니다. 예시 데이터에는 별도 집계 예외를 두지 않습니다. 설정에서 예시만 삭제할 수 있습니다.

## AI 작성 흐름

1. 경험을 입력하고 `AI와 경험 구체화`를 누릅니다.
2. 부족한 정보에 대한 질문 하나가 표시됩니다. 답변을 반영하면 다음 질문 또는 정리 결과를 받습니다.
3. 최초 원문과 질문·답변을 함께 보존합니다. `AI 정리 후 저장`은 서버에서 원문에 근거한 정리본을 생성합니다.
4. `원문 저장`은 AI를 호출하지 않고 원문과 기본 문장 추출본을 저장합니다. AI 실패 시 자동으로 다른 결과를 저장하지 않습니다.

AI 응답은 JSON 구조와 근거 기록 ID를 검증하지만 사실 정확성을 보증하지는 않습니다. 결과와 원문을 함께 확인하세요. 요청은 사용자가 버튼을 누를 때만 발생합니다. 편집 중 입력은 탭의 sessionStorage에 임시 보존됩니다. 면접 연습 답변도 해당 탭에 임시 보존되며 계정 간 동기화되지 않습니다.

자소서 추천은 선택한 카테고리의 최근 60개 기록, 학기 비교는 학기별 최근 30개 기록을 사용합니다. 각 기록의 원문 앞 1,500자와 정리본·태그를 전달합니다. 결과에 사용한 기록 개수를 표시합니다. 단일 경험의 꼬리질문·정리·면접 질문은 원문 전체(최대 20,000자)를 사용합니다.

## 주기와 날짜

- 날짜는 한국 시간입니다. 활동 날짜와 실제 작성 날짜를 별도로 저장합니다.
- 시작일부터 매일, 매주, 매월 또는 직접 설정한 1~365일 주기로 계산합니다. 값 30은 달력 기준 매월입니다.
- 매월은 시작일의 날짜를 유지하며 해당 날짜가 없는 달에는 월말을 사용합니다. 예: 1/31 → 2/28 → 3/31.
- 한 기간에 기록을 하나 이상 생성하면 완료입니다. 과거 활동을 오늘 입력해도 오늘 속한 기간에만 반영됩니다.
- 진행 중인 기간을 아직 작성하지 않았더라도 직전 기간까지의 연속 횟수는 유지합니다. 미작성 기간이 마감되면 끊깁니다.
- 시작일 이전 기록과 미래 작성 시각은 완료 계산에서 제외합니다. 미래 시작일은 시작 예정으로 표시합니다.
- 주기·시작일 변경 시 현재 설정으로 기존 작성 시각을 다시 계산합니다. 그룹 멤버도 각자의 설정을 따릅니다.
- 연속 기간 10주·20주부터 프로필 불꽃 표시가 강화됩니다.
- 1학기는 3~8월, 2학기는 9월~다음 해 2월입니다.

## 공개 범위

- **비공개:** 본인만 원문과 정리본을 열람합니다.
- **그룹 공개:** 본인과 하나 이상 같은 그룹에 속한 사용자만 열람합니다.
- **전체 공개:** 서비스의 모든 인증 사용자가 열람합니다. 비로그인 웹 전체에 공개하는 설정은 아닙니다.
- 각 기록은 프로필 설정을 따르거나 공개 범위를 개별 지정할 수 있습니다. 프로필 기본값 변경은 이를 따르는 기존 기록에도 적용됩니다.
- 서버에서 권한을 검사합니다. 다른 사람의 공개 기록을 수정하거나 AI 분석 대상으로 지정할 수는 없습니다.

## 저장·마이그레이션·인증

로컬 데이터는 `.data/aimers.sqlite`에 저장합니다. `AIMERS_DATA_DIR`와 `PORT` 환경 변수로 위치·포트를 변경할 수 있습니다. 기존 SQLite는 서버 시작 시 `0001_profiles.sql`을 한 번 적용합니다. 기존 브라우저 쿠키는 유지하면서 공개 사용자 ID에서 세션 값을 분리합니다.

로컬은 127.0.0.1 전용 체험 서버이며 쿠키로 사용자를 구분합니다. 쿠키 삭제 후 계정 복구는 제공하지 않습니다. 호스팅은 Sites 인증 게이트웨이가 제공하는 사용자 ID와 D1 바인딩을 사용합니다.

## 검증 및 배포 빌드

```powershell
node --test tests/*.test.mjs
node scripts/build.mjs
node --check dist/server/index.js
```

테스트는 AI 오류/응답 검증, 원문 보존, 사용자별 AI 데이터 분리, 공개 범위, 기간 경계와 월말·윤년, SQLite 마이그레이션·기존 쿠키 호환을 포함합니다.

기본 고딕 글꼴은 Pretendard Variable 1.3.9이며 `public/fonts/PretendardVariable.woff2`에서 직접 제공합니다. OFL 라이선스는 같은 폴더의 `OFL.txt`에 보존합니다. 외부 폰트 CDN 요청 없이 로컬 서버와 Worker가 같은 파일을 제공합니다.

빌드는 글꼴과 라이선스를 포함한 여섯 개의 정적 에셋과 API를 단일 Worker `dist/server/index.js`로 묶습니다. 실제 배포에는 기존 `.openai/hosting.json` 설정, D1의 `0000_aimers.sql`과 `0001_profiles.sql` 순서 적용, Worker secret `DEEPSEEK_API_KEY` 설정이 필요합니다. 이 변경에서 외부 배포는 수행하지 않았습니다.

## 남아 있는 범위

앱 내부 알림은 화면이 열려 있을 때 갱신됩니다. 앱을 닫은 동안의 푸시·이메일·예약 발송, 결제, 댓글은 제공하지 않습니다. 음성 입력은 브라우저 SpeechRecognition 지원과 마이크 권한에 따라 달라지며 실제 마이크 입력은 검증하지 않았습니다. JSON 가져오기는 한 번에 50개까지이며 전체 내보내기 파일이 이보다 크면 나눠 등록해야 합니다.

## 빠른 메모, 회고와 면접 질문

대시보드의 빠른 메모는 내용만 입력해 바로 저장합니다. 회고 작성에서 날짜와 메모를 고르면 AI가 기록 속 장면에 맞는 질문을 최대 3개씩 만들고, 답변을 회고에 반영합니다. 원본 메모는 따로 보존합니다.

면접 질문은 지원 직무와 관점을 선택해 5개씩 생성합니다. 각 질문에 꼬리질문과 답변 점검 항목을 제공하며 새 질문을 받아도 이전 답변은 유지합니다. 질문 구성의 근거와 한계는 [질문 설계 문서](docs/interview-question-design.md)에 정리했습니다.

실제 생성에는 서버 환경의 DEEPSEEK_API_KEY가 필요합니다. 로컬 DB는 서버 시작 시 새 기록 유형을 위한 마이그레이션을 자동 적용합니다. D1 환경에서는 배포 전에 drizzle/0002_record_workflows.sql을 별도로 적용하세요.
