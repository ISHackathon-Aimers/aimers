# AIMers

사건은 한두 줄로 기록하고, 기간별 회고에서 AI 질문에 답하며 자세히 돌아보는 앱입니다. 기록, 회고, 그룹, 프로필과 면접 답변을 서버 데이터베이스에 저장합니다.

## 실행

Node.js 24 이상이 필요합니다. 외부 npm 패키지나 별도 DB 서버는 필요하지 않습니다.

1. .env.example을 참고해 .env를 작성합니다. 기존 .env를 덮어쓰지 않습니다.
2. node server.mjs로 실행합니다.
3. 기본 주소는 http://127.0.0.1:4173 입니다.

서버는 .env를 자동으로 읽습니다. .env와 데이터베이스는 Git에서 제외합니다. API 키는 서버에서만 사용하며 빌드 산출물에 포함하지 않습니다.

## Google 로그인

1. Google Cloud에서 웹 애플리케이션용 OAuth 클라이언트를 생성합니다.
2. 승인된 리디렉션 URI에 http://127.0.0.1:4173/api/auth/google/callback 을 등록합니다.
3. .env의 GOOGLE_CLIENT_ID와 GOOGLE_CLIENT_SECRET을 설정합니다.
4. APP_ORIGIN을 실제 접속 주소와 맞추고 서버를 재시작합니다. localhost와 127.0.0.1은 서로 다른 주소입니다.
5. 동의 화면이 테스트 상태이면 사용할 계정을 테스트 사용자로 등록합니다.

Google 설정이 없으면 로그인 준비 화면을 표시합니다. 기본 모드에서는 비로그인 데이터 API 요청을 거절합니다. 본인 PC의 체험 모드는 AIMERS_DEMO=1로 명시해서 사용합니다. 체험 기록과 Google 계정 기록은 분리되며 자동 합치지 않습니다.

서버는 authorization code, PKCE, state와 nonce를 검증합니다. Google 공개키로 ID 토큰 서명을 검증하고 발급자, 클라이언트 ID, 만료 시각과 인증된 이메일을 확인합니다. Google 액세스 토큰이나 비밀번호를 보관하지 않습니다. 세션은 무작위 토큰의 SHA-256 해시로 DB에 저장하고 30일 후 만료합니다.

계정 설정은 이메일, 로그아웃, 모든 기기 로그아웃과 계정 삭제를 제공합니다. 계정 삭제는 개인 기록과 면접 답변, 소유한 그룹을 삭제합니다. 다른 사용자의 개인 기록은 유지합니다.

Google 실계정 로그인은 OAuth 클라이언트 생성 후 검증해야 합니다. [Google 공식 설정 안내](https://developers.google.com/identity/openid-connect/openid-connect)를 참고합니다.

## AI

.env에 DEEPSEEK_API_KEY를 설정합니다. 기본 모델은 deepseek-flash이며 DEEPSEEK_MODEL로 변경할 수 있습니다. 요약, 회고 질문, 면접 질문, 경험 추천과 학기 보고서를 실제 DeepSeek API로 생성합니다. 키가 없거나 AI 호출이 실패해도 원문 저장은 가능합니다. 실패를 고정된 시연 답변으로 바꾸지 않습니다.

회고와 면접 질문은 NAVER와 토스의 공식 채용 안내를 포함한 자료의 질문 전개 방식과 직접 작성한 few-shot 예시를 참고합니다. 예시 사건을 사용자 기록에 섞거나 고정 문항을 돌려 쓰지 않도록 지시합니다. 근거 구절, 기록 ID, 관점 중복과 JSON 형식을 검증합니다. 이 검사는 의미적 정확성을 보장하지 않으므로 결과를 원문과 함께 확인해야 합니다. 참고 자료는 앱 화면에 표시하지 않습니다.

AI 생성 경로는 계정당 시간당 30회로 제한합니다. 상세 정리 후 저장은 별도의 기록 저장 경로입니다. 회고에 연결한 긴 경험은 앞 2,000자, 자소서 추천은 최근 60개, 학기 보고서는 학기별 최근 30개를 사용합니다.

## 기록과 공개 범위

- 경험은 한두 줄로 즉시 저장합니다. 첫 줄에서 제목을 만들고 날짜와 공개 범위는 필요할 때 펼칩니다. 새 경험 메모는 최대 2,000자입니다. 기존 긴 경험의 원문은 유지합니다.
- 회고는 기간 안의 기록을 최대 20개 연결하고 AI 질문에 답해 구체화합니다. 연결한 경험 원문을 덮어쓰지 않습니다.
- 해시태그는 화면에서 입력하거나 표시하지 않습니다. 서버에서 내부 분류를 저장하며, 이는 사용자의 역량을 확정하는 평가가 아닙니다.
- 면접 질문과 답변은 경험별 최근 24개를 계정에 자동 저장합니다. 경험과 회고의 작성 중 초안은 현재 탭에 임시 보관하므로 저장 버튼을 눌러야 서버에 반영됩니다.
- 기록마다 비공개, 같은 그룹에 공개, 인증된 서비스 사용자에게 공개를 선택할 수 있습니다. 공개 시 원문도 함께 열람할 수 있습니다.
- 그룹, 알림, 가져오기와 내보내기, 기록 주기와 연속 기록 계산을 유지합니다. 화면의 글꼴과 글씨 크기 설정은 제거했습니다.

## 데이터베이스와 운영

로컬 DB는 .data/aimers.sqlite이며 SQLite WAL을 사용합니다. 초기 서비스는 한 Node.js 프로세스로 실행할 수 있어 대형 서버나 DB 클러스터가 필요하지 않습니다. 실제 부하 한계는 측정하지 않았습니다. 동시 쓰기가 많아지면 서버와 저장소 구성을 다시 검토해야 합니다.

기존 DB에는 시작 시 0001_profiles, 0002_record_workflows와 0003_auth를 필요한 순서로 적용합니다. DB 경로는 AIMERS_DATA_DIR로 변경합니다. 운영 백업은 SQLite의 일관된 백업 기능을 사용합니다. 실행 중인 WAL DB 파일 하나만 복사하면 최근 변경을 놓칠 수 있습니다.

외부 공개는 HTTPS 리버스 프록시를 준비하고 APP_ORIGIN을 실제 HTTPS 주소로 지정합니다. 필요하면 HOST=0.0.0.0을 사용합니다. 체험 모드는 외부 도메인에서 허용하지 않습니다. 포트 변경 시 PORT, APP_ORIGIN과 Google 콜백 주소를 모두 맞춥니다. 운영자는 DB 백업, 프로세스 재시작과 모니터링을 준비해야 합니다. 이 작업에서 외부 배포는 수행하지 않았습니다.

Worker 빌드는 D1을 지원합니다. 배포 전 drizzle의 0000부터 0003까지 마이그레이션을 적용하고 DEEPSEEK_API_KEY, GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET과 APP_ORIGIN을 환경 설정에 등록합니다. Worker도 Google 세션으로 인증하며 임의의 사용자 ID 헤더를 신뢰하지 않습니다.

## 검증

npm test, npm run build, node --check dist/server/index.js를 실행합니다. 테스트는 원문 보존, 사용자별 접근 권한, 질문 근거, 면접 답변 저장, Google 서명과 클레임, state 재사용 방지, 세션 만료와 폐기, 계정 삭제를 포함합니다. 실제 DeepSeek 호출도 별도로 확인했습니다.

푸시 알림, 이메일 발송, 결제와 댓글은 제공하지 않습니다. 음성 입력은 지원 브라우저와 마이크 권한이 필요합니다.
