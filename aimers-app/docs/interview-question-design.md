# 회고와 면접 질문 설계

확인일: 2026-11-08

## 참고 자료와 적용 범위

- [Google re:Work의 구조화 면접 가이드](https://rework.withgoogle.com/intl/en/guides/a-guide-to-structured-interviewing-for-better-hiring-practices)는 실제 행동을 확인하는 질문과 가상 상황 질문을 구분하고, 추가 질문으로 판단 과정을 확인하는 방식을 설명한다. 팀에 기여한 경험에 대한 시작 질문과 목표, 동료 반응, 다음 계획을 묻는 후속 질문의 예시를 제공한다. 앱은 이 구조를 사용자의 기록에 맞게 재작성한다.
- [Microsoft Careers의 면접 안내](https://careers.microsoft.com/v2/global/en/hiring-tips/interview-tips)는 구체적인 상황, 행동, 결과와 회고를 설명하고 피드백 반영, 협업, 접근 방식의 변화를 준비하도록 안내한다. 앱의 학습과 다음 행동 관점에 반영한다.
- [Amazon Jobs의 FEE 면접 안내](https://amazon.jobs/content/en/how-we-hire/fee-interview-prep)는 과거 행동과 결정 이유, 성공과 어려움, 가능한 경우 결과 근거를 확인하는 방식을 안내한다. 특정 직무에 대한 가이드이므로 모든 회사와 직무의 실제 기출로 일반화하지 않는다.

공식 안내와 공개 예시를 참고한 연습 질문이다. 특정 회사에서 실제로 출제된 문항을 복원한 데이터베이스가 아니며, 사용자 경험에 없는 사실이나 성과를 만들지 않는다.

## 두 가지 기록 흐름

- 빠른 메모는 내용만으로 즉시 저장한다. 제목은 첫 줄에서 만들며 최대 2,000자다. AI 연결 없이 저장할 수 있고 처음에는 비공개다.
- 회고에서는 기간 안의 메모와 경험을 최대 20개 선택한다. 개인 주기의 기본 기간을 제공하며 이전 주를 돌아볼 때는 날짜를 바꿀 수 있다.
- 메모와 회고는 별도 기록이다. 연결한 메모의 원문을 회고 답변이나 AI 요약으로 덮어쓰지 않는다.
- 회고 질문과 답변은 회고 원문과 구조화된 대화 이력에 함께 보존한다. 작성 중 질문과 답변은 같은 탭의 임시 저장으로 복구한다.
- 기록 유형, 연결 정보와 대화 이력은 내보내기와 가져오기에 포함한다. 함께 가져온 메모의 id는 새 기록의 id로 연결한다.

## 질문 품질 규칙

- 회고는 원문과 선택한 메모, 이전 질문과 답변을 함께 읽고 최대 3개 질문을 만든다. 서로 다른 메모가 있다면 둘 이상을 다룬다.
- 질문은 원문의 구체적 구절을 포함하고 개인 기여, 판단, 문제 정의, 협업, 검증, 학습, 제약, 사용자 관점, 가상 상황, 다음 행동 중 서로 다른 관점을 사용한다.
- 면접 연습은 한 번에 5개 관점과 질문별 꼬리질문 2개, 답변 점검 항목 3개를 제공한다. 지원 직무와 연습 관점을 선택할 수 있다.
- 최근 질문의 관점과 문장을 다음 생성에 전달한다. 동일 문장, 중복 관점, 원문에 없는 근거, 다른 사용자의 메모 인용은 거절한다.
- 면접 질문에는 가상 상황 관점을 하나 포함하고 실제 일어난 일과 구분하도록 지시한다. 갈등이나 실패가 없으면 있었다고 전제하지 않는다.
- 구조와 근거 검사에서 실패하면 한 번 다시 생성한다. 다시 실패하면 원문과 답변을 보존하고 재시도를 안내한다. 이 검사는 문장의 의미나 실제 면접 적중도를 보장하지 않는다.
- 새 면접 질문을 생성해도 기존 답변은 유지한다. 같은 탭에서 최근 24개 질문과 답변을 보관한다.

## 실행과 검증

기존 로컬 SQLite는 서버 시작 시 0002_record_workflows.sql을 한 번 적용한다. D1 배포 환경은 배포 전에 같은 마이그레이션을 별도로 적용해야 한다.

실제 AI 질문 생성에는 서버의 DEEPSEEK_API_KEY 설정이 필요하다. 자동 테스트는 대체 응답으로 저장, 권한, 질문 근거와 중복 검사, 실패 복구를 검증한다. 실제 모델 응답의 품질 평가는 별도다.
